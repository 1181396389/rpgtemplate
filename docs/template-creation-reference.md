# RPG转生模板（rpgtemplate）· 角色模板制作总参考规范

本文档为 `rpgtemplate` 模组**所有角色模板、进阶/同源分支及模板内绑定道具**的最高制作参考准则。任何新建或修改角色模板的设计与代码实现，均必须严格满足以下规范（注：非模板玩家专用的外部独立武器如 `nt_mimic_blade` 不在本规范约束范围内）。

---

## 一、 核心铁律：限制与弱点（强制写入与执行）

所有角色模板在设计数值、技能机制、被动体质与模板自带道具时，必须无条件遵循以下三条核心规则：

- **使用限制**：威力强制锚定。无论模板原主强度如何，其实际效果（伤害、防御力、道具威力）完全取决于使用者当前的面板等级与属性。若使用者等级极低，使用高阶模板的大招可能会因能量不足无法发动或是威力不足。
- **反噬/副作用**：完美继承角色负面效果和弱点以及癖好。如抽取“身患重症的绝世天才”，使用者在载入该模板后会同步获得对应模板时期的相应的身体体质与病症以及才华。
- **克制关系**：机制级技能（如：必死、绝对催眠等）需经过等级/属性判定。判定结果由强至弱分为：1.完全生效；2.显著干扰；3.微弱牵制；4.判定失败。

---

## 二、 三大铁律的数值与代码落地细则

### 1. 使用限制：威力强制锚定（严禁硬编码越级数值）

1. **技能伤害、治疗与护盾强制走面板公式**
   - 主动与被动技能造成的伤害、治疗、护盾吸收量及模板内召唤/生成道具威力，必须基于使用者当前的 `PlayerSystemData`（系统等级 `data.level()`、面板属性 `StatCalculator`、技能系数 `SkillContext.damage(coefficient)`）动态结算。
   - **严禁**在角色模板逻辑中写死固定高额常数或无视使用者面板的固定秒杀数值。
   - 若原著机制包含百分比持续伤害（如流血、黑炎灼烧），其单跳伤害必须受使用者当前面板基准威力的倍率封顶。
   - 叠层成长型被动（如战斗适应、剑意蓄势等）**必须设置与当前等级挂钩的叠层上限与脱战衰减**，严禁无限叠层导致数值脱离面板锚定。

2. **防御力与减伤强制锚定当前等级与防御面板**
   - 减伤、抗性与护体效果必须以使用者的实际系统等级（`data.level()`）与防御面板（`defense`）为基准计算，严禁低等级载入高阶模板即直接无条件获得 100% 绝对免伤。

3. **高阶模板大招的能量门槛校验**
   - 系统品阶消耗倍率（`Quality.costMultiplier`）如下表所示：

   | 品阶 (`Quality`) | 抽取权重 | 默认等级上限 (`maxLevel`) | 属性加成倍率 (`bonusMultiplier`) | 消耗倍率 (`costMultiplier`) | 规则判定加成 (`ruleBonus`) |
   | :--- | :---: | :---: | :---: | :---: | :---: |
   | `BASE` | 0 | 0 | 0.5× | 1.0× | +0 |
   | `N` | 40 | 10 | 1.0× | 1.0× | +0 |
   | `R` | 30 | 20 | 1.5× | 2.0× | +1 |
   | `SR` | 18 | 30 | 2.2× | 4.0× | +2 |
   | `SSR` | 8 | 40 | 3.2× | 8.0× | +3 |
   | `UR` | 3.5 | 50 | 4.5× | 16.0× | +5 |
   | `EX` | 0.5 | 60 | 6.0× | 32.0× | +8 |
   | `EX_PLUS` | 0.15 | 70 | 8.0× | 64.0× | +10 |
   | `LR` | 0.05 | 80 | 10.0× | 128.0× | +12 |
   | `MR` | 0.01 | 90 | 12.0× | 256.0× | +15 |

   - 技能的 `base_cost` 必须结合品阶消耗倍率与模板属性加成设定合理数值，严禁将高阶大招设成极小小数导致零门槛连发。
   - **验收标准**：当 `Lv.1 ~ Lv.3` 低等级玩家载入高阶模板时，其终极奥义所需 MP/SP 应高于或接近当前能量池上限（出现因能量不足无法发动，或勉强施放一击即力竭且仅打出低等级面板威力的效果）。

### 2. 反噬/副作用：完美继承负面效果、弱点及癖好

1. **按原著角色时期精准切片（才华与病痛一体两面）**
   - 模板抽取的是**特定时期的具体角色状态**，而非只取正面能力的纯净技能包。
   - 同一角色的不同人生阶段应拆分为独立的模板或进阶/同源节点（`advancement_of` / `lineage`），每个节点同步绑定该时期的身体体质、旧伤病症、精神隐患与性格癖好：
     - *示例 A（身患重症的绝世天才，如肺痨期冲田总司 / 残躯期宇智波鼬）*：获得顶尖剑技或瞳术才华的同时，同步载入肺痨咳血或视力模糊血疾，高频爆发会触发反噬硬直与生命折损。
     - *示例 B（容器受肉期宿傩）*：同步载入容器压制（封印技能）与灵魂创伤破绽。
     - *示例 C（异想体 O-06-20 一无所有）*：同步载入精神/灵魂破绽、拙劣拟态躯壳对人类精密装备的排斥、人皮腐朽及破碎模仿音交互癖好。

2. **JSON 数据层必填三类负面与性格字段（严禁留空）**
   - 除 `BASE` 基础模板外，所有角色模板在 `data/rpgtemplate/rpg_templates/<id>.json` 中**必须明确定义并在代码与 UI 中实装以下三组词条**：
     - **`weaknesses`（弱点）**：属性克制易伤、致命命门破绽、特定状态衰弱等。
     - **`negatives`（负面状态/体质病症）**：载入模板即同步挂载的生理病症、身体缺陷、过载烧毁/反噬等。
     - **`quirks`（癖好）**：符合角色人设与本能的行为逻辑约束与正负反馈（顺应角色本性可加速模板契合度经验获取，违背本性则触发惩罚或衰减）。

3. **状态挂载与卸载隔离铁律（严防跨模板泄漏）**
   - 任何模板专属的被动、形态属性、弱点与病症监听器，**必须同时校验系统已激活且当前载入模板 ID 精确匹配**：
     ```java
     PlayerSystemData data = SystemDataManager.get(player);
     if (!data.isActivated() || !TEMPLATE_ID.equals(data.loadedTemplateId())) {
         return;
     }
     ```
   - 玩家卸载（`unload`）或切换模板时，必须立即清除该模板写入玩家实体的临时 `AttributeModifier` 与瞬时状态。

### 3. 克制关系：机制级技能四档等级/属性判定

1. **必须接入判定的“机制级技能”范围**
   凡具有“概念改写、规则压制、无视常规攻防”特征的模板能力（如：必死/强制斩杀、绝对催眠/精神幻术控制、概念必中破防/无视护甲、削减最大生命上限、巧手缴械夺取、越级绝对免疫等），**一律禁止写成无条件 100% 生效**，必须经过等级与属性对抗判定（统一调用 `RuleJudge.evaluate(...)`）。

2. **四档判定结果标准定义与降级表**
   设施放者有效规则强度为 $\text{Lv}_{\text{caster}} + \text{Quality.ruleBonus} + \text{属性修正}$，目标有效规则抗性为目标系统等级与模板品阶加成，对抗净差值为 $\Delta$。判定结果由强至弱严格分为四档（对应 `message.rpgtemplate.rule.full / major / minor / fail`）：

   | 档位 | 判定结果 | 必死 / 强制斩击类表现 | 绝对催眠 / 精神幻术类表现 | 破防 / 削上限 / 缴械类表现 |
   | :---: | :--- | :--- | :--- | :--- |
   | **1** | **完全生效** (`rule.full`) | 完整触发无视无敌帧斩击/处决规则 | 完整控制时长与精神重创 | 100% 穿透防御 / 满额削上限 / 成功缴械 |
   | **2** | **显著干扰** (`rule.major`) | 降级为常规技巧重创伤害 + 短暂减速 | 控制时长大幅缩短，附带失明/迟滞 | 穿透 50% 防御 / 削上限减半 / 仅造成破绽减速 |
   | **3** | **微弱牵制** (`rule.minor`) | 仅造成低倍率擦伤 | 无法定身，仅造成短暂恍惚减速 | 穿透 20% 防御 / 微幅削减 / 轻微打断 |
   | **4** | **判定失败** (`rule.fail`) | 规则被高位格震碎，仅余微弱余波且自身受反震 | 幻术被看破震碎，施术者遭受精神反噬 | 规则完全失效，无法撼动目标 |

## 四、 模板提交与合入前自检清单（Checklist）

- [ ] **【使用限制】** 模板技能、持续伤害、回血与模板内道具威力是否 100% 锚定使用者当前等级与面板属性？是否设置了叠层上限与合理的高阶 MP/SP 消耗门槛？
- [ ] **【反噬/副作用】** JSON 与服务端逻辑是否完整实装了对应原作时期的 `weaknesses`、`negatives` 与 `quirks`？
- [ ] **【反噬/副作用】** 服务端事件处理器是否严格校验 `data.isActivated() && TEMPLATE_ID.equals(data.loadedTemplateId())`，卸载后绝不污染其他模板？
- [ ] **【克制关系】** 必死/斩杀、绝对催眠/强控、概念破防、削生命上限等机制级技能是否均已接入 `RuleJudge` 四档判定（`1.完全生效 / 2.显著干扰 / 3.微弱牵制 / 4.判定失败`）？
- [ ] **【UI 可见性】** 系统面板（K 键）与左上角 HUD 是否能正常查看该模板的被动、弱点、病症、癖好与实时状态提示？
