# 大刀类物品建模（分段薄板 + 接头块）

依据：`minecraft-modeling-item` skill 的规则（斜面用旋转长方体，不堆扫描切片；硬边像素；交付前多视角检查与审计），以及用户上传的月亮计划枪包中拟态枪模型的刀身结构（见第 6 节）。

## 1. 比例（先于建模）
- 刃身长度 L≈22（刃根 y=4，刃尖 y=26）；刃根总宽约 5.2（背边半宽 2.2 + 刃边半宽 1.8 ≈ 4.0，颈部另加宽）。
- 金属刃：一侧为不对称外凸弧线，从刃根向刃尖收窄至 0。
- 血肉：背边为直线（不弯曲）。
- 无护手。刃根以下为血肉材质的倒三角颈部，汇入剑柄。
- 忽略参考图中持刀的角色。

## 2. 几何规则（当前版本 v22）
- 坐标：刃身沿 +Y，中心线 x=8，厚度沿 Z。
- 血肉 `FLESH_Z = (6.9, 8.1)`，厚 1.2；金属 `STEEL_Z = (7.3, 7.7)`，厚 0.4；眼睛 z 5.3 起，凸出到血肉正面 z=6.9。
- 分段：`N_SEG = 24`（血肉与金属各 24 段）。每段以相邻两个节点中心之间的弦为轴，做一块绕 Z 轴旋转的长方体，旋转角 = −atan(dx/dy)。
- 金属刃从第 3 个节点开始（`STEEL_START_NODE = 3`，约 t=0.125），即刃根附近，不延伸到颈部。
- 节点接头块：每个节点补一块，宽度为该节点刃身宽度，高 0.6，z 向两侧各缩进 0.1（避免与刃身同平面的面互相打架）。刃尖宽度为 0 的节点不生成。
- 颈部：6 段，从 `GUARD_Y=4` 到 `NECK_BOTTOM_Y=0.6`，底端半宽 0.9，顶端左侧伸到 `x_flesh_outer(0)`，右侧到 `CX+2.4`。
- 轮廓函数：背边 `FLESH_HALF = [(0,2.2),(1,0)]`（直线）；刃边 `STEEL_OUT = [(0,1.8),(0.2,2.1),(0.45,1.85),(0.75,1.0),(1,0)]`（不对称外凸）；金属宽度 `STEEL_W = [(0,0.9),(1,0.25)]`。
- 预算：110 个元素，660 个面（上限 512 块，以元素计）。

## 3. 贴图规则（当前版本 v22）
- 贴图 `TEX = 128`，与枪包 `redmit_geo.json` 的 texture 128 一致。`PX = TEX/16 = 8` 像素/单位，所有元素同一密度。
- 配色取自枪包 `assets/limbus/textures/gun/uv/redmit.png`：
  - 血肉：(129,16,16) 主色，(97,40,39) 纤维暗色，(140,16,16) 高光斑，(115,30,30) 裂纹，(32,32,32) 外缘描边。
  - 金属：(169,169,169) 主色，(235,229,227) 刃口高光，(32,32,32) 背光暗边，(120,120,124) 纹理线。
  - 骨刺：(206,190,165) 主色，(119,115,98) 根部边，(235,229,227) 中线高光。
  - 握柄：(32,32,32)，高光 (60,60,60)。
  - 眼睛：白色眼白 (235,229,227)、瞳孔 (14,12,20)、高光 (255,255,255)；蓝虹膜 (70,150,246)/(28,66,140)，绿虹膜 (80,210,190)/(24,96,88)。
- 纹理方向：血肉用横向纤维纹与少量裂纹；金属用纵向亮暗线；骨刺用中线高光。
- 纯色面（接头块、握柄、其他共用材质）用 2×2 的共用色块，不占单独的像素区域。
- 血肉细节用确定性规则（纤维、裂纹、高光斑），不用随机噪点，不用柔边。
- 不要在 32×32 下画眼睛：3×3 以下画不出虹膜（v12 的蓝眼 2×2 消失，v13 修复）。

## 4. 生成、预览与审计（流程）
1. 运行 `build_mimic.py`，先确认退出码为 0。
2. 生成成功后再运行审计：`audit_model.py <json> --profile java-1.21.6 --assets-root assets --output audit_report.json`，要求 0 错误、0 警告。
3. 审计若在生成失败后运行，会读取旧 JSON 并给出假通过。每次生成前先删掉旧 JSON。
4. 查看 `preview_front.png`（从 −Z 看）和 `preview_side.png`（从 −X 看）。预览按深度从远到近绘制，深度写反会让眼睛被血肉盖住（曾出过这个错误）。
5. `viewer_mimic.html` 由 `build_mimic.py` 的 `main()` 一并生成，嵌入当前模型与贴图；生成后检查它的时间与模型 JSON 一致。
6. 运行时（手持位置、旋转方向）尚未在游戏内验证。

## 5. 骨刺、眼睛、握柄（当前版本 v22）
- 剑柄与配重各一个块：
  - 握柄：x ±0.4，y −4.2…0.8，z 7.2…7.8。
  - 配重：x ±0.8，y −5.0…−4.2，z 7.0…8.0。
  - 参考：用户上传的 image-20（绿幕上的圆头黑色配重）。
- 骨刺共 5 根：
  - 前两根：根部贴在血肉正面，位于刃边内侧，`xa = 刃边内缘 − 0.2`（不穿进刃身，也不悬空），在 XY 平面内向金属刃外侧伸出，旋转 +34°。位置按用户画的黄线换算：上方 t≈0.23（x=10.65），下方 t≈0.03（x=10.37）。
  - 背边三根：根部在背边上，朝 −34° 向外伸出，t 分别为 0.30、0.38、0.46，尖端长度依次变短（底段长 1.6/1.4/1.2，尖段 1.1/0.9/0.8）。
- 眼睛：
  - 绿色大眼：边长 2.6，t=0.14（刃根附近）。
  - 蓝色小眼：边长 1.6，t=0.57（中上部）。
  - 位置是按用户标注估的，尚未确认。

## 6. 参考：月亮计划枪包中的拟态刀身（学习结论）
参考文件：`/home/user/workspace/reference/limbus_redmit_blade_notes.md`；枪包解压于 `/home/user/workspace/reference/limbus_pack/`。

### 事实（来自 `assets/limbus/geo_models/gun/redmit_geo.json`）
- 刀身是 `blade`、`blade2`…`blade7` 等组，共约 365 个立方体。约 353 个是 0.6–0.65 厚的薄板；约 193 个是 ≤1.5 的接头小块；约 37 个是长条（≥6）。
- 旋转角是固定步进：−10°、−45°、−71°、−90°、−135°、90°、129°、165°，不是任意角。
- 接缝靠小接头块盖住，段与段不要求严格对齐。
- 贴图 128，配色见第 3 节。

### 我们从中学到并落地的四条规则
1. **薄板**：刃身用薄板（厚度远小于长度）沿边串接，不用厚段叠加。当前血肉厚 1.2、金属厚 0.4。
2. **小角度步进**：段数足够多，每段转角小，才能接近参考的固定步进。14 段台阶明显，24 段平滑。
3. **接头块**：节点处补小块，盖住角缝。接头块要比刃身稍微缩进，避免同平面面打架。
4. **128 贴图 + 共用纯色**：贴图提高到 128 后，所有元素同一像素密度；接头块与握柄用共用纯色，不占单独区域。

### 没有照搬的部分
- 不逐块复刻枪包的 365 立方体。我们只取上面四条规则。
- 枪包的骨骼层级（blade → bone2 等）和动画未纳入，本模型是静态物品模型。

## 7. 教训与排错（按出现顺序整理）
- **段间重叠 → 闪烁**：v7 出现过。段间只在端点相接，不要用重叠消除缝隙，用接头块。
- **14 段的台阶与漏缝**：角接不上，外缘呈台阶。补接头块后缝隙明显减少（v19）。减到 8 段更差（v19 试验，已撤回）。
- **接头块与刃尖**：刃尖宽度为 0，不要生成接头块，否则审计报 `plane_elements`。
- **贴图溢出**：16 段在 32×32 下打包溢出；接头块用独立贴图区域也会溢出。改用共用纯色、或提高贴图分辨率。
- **刺悬空或穿透**：前刺根部要贴在血肉正面或刃边内侧，压进约 0.2–0.4，不要完全在外面（会悬空），也不要穿到刃身后面（会卡住）。厚度变化后，所有写死的 z 坐标都要跟随 `FLESH_Z` 计算。
- **左右镜像**：用户的标注图与预览左右是镜像的。图中左侧 = 模型 +x（金属刃一侧）。按标注换算坐标前先确认方向。
- **眼睛消失**：小尺寸眼睛在贴图上占的像素太少就会只剩白块。至少 3×3 像素。
- **假通过**：审计读的是旧 JSON，先删旧文件再生成。
- **预览颜色**：预览是平面着色，眼睛在预览里显示为灰白，这不影响贴图。
